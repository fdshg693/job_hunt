# writing-skill スキルについて

`writing-skill` は「スキルの作り方・評価の仕方」自体を扱うメタスキルである。このファイルは人間のメンテナ向けで、設計意図とファイル間の役割分担をまとめる。Claudeが実行時に読むのは[SKILL.md](SKILL.md)であり、こちらは参照しない。

## 位置付け

`SKILL.md`本体は「新規作成/編集か、評価か」を判定して該当ファイルに読み替えるだけのルーターであり、実際の手順・判断基準は本文に書かず全て別ファイルに分離してある。これは[writing.md](writing.md)自身が定義する「条件分岐がある場合の設計判断」（呼び出し目的が1つで内部の観点だけ変わる場合は1スキル+ルーター構成にする）を自己適用した結果であり、`writing-skill`自身がそのお手本を兼ねている。

## 各ファイルの役割分担

| ファイル              | 役割                                                                                                                 | 読まれるタイミング           |
| --------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `SKILL.md`            | 「作成/編集か評価か」の分岐のみ。手順は持たない                                                                      | 常にスキル呼び出し時         |
| `writing.md`          | 新規作成・既存編集の実際の手順、条件分岐の設計判断                                                                   | 作成・編集フローに入った時   |
| `evaluating.md`       | 既存スキルの評価手順、複数スキル一括評価時のサブエージェント委譲戦略とプロンプト例                                   | 評価フローに入った時         |
| `bestpractices.md`    | `writing.md`・`evaluating.md`双方が参照する共通チェックリスト（唯一の正）                                            | チェックリスト照合が必要な時 |
| `skills-reference.md` | Claude Codeのスキル機構自体（配置場所・frontmatter全フィールド・動的コンテキスト注入・置換変数）の網羅的リファレンス | 機構の細部を確認したい時     |

チェックリストの実体は`bestpractices.md`にしかない。`writing.md`・`evaluating.md`に同じ基準を書き写さないこと（重複すると片方だけ更新されて食い違う）。

## 一括評価時のサブエージェント委譲閾値について

[evaluating.md](evaluating.md)は評価対象が3件以上になったら必ずサブエージェントに委譲するとしている。この閾値は「全`SKILL.md`と同梱ファイルを自分のコンテキストに読み込むだけで大量のトークンを消費し、以降のやり取りの質が落ちる」という理由に基づく。2件以下を自分で評価する場合との境目を変える場合は、この根拠（コンテキスト消費の見合い）が変わったかどうかを確認してから閾値を調整すること。

## 保守時の注意

- `skills-reference.md`はClaude Code公式ドキュメント（`code.claude.com/docs/en/skills`等）の内容を転記・要約したものであり、一次情報ではない。frontmatterフィールドの追加・変更などバージョンアップで公式側が変わった場合、この転記内容は自動追随しない。致命的な相違に気づいたら公式ドキュメントで最新化を確認し、手動でこのファイルに反映する
- `bestpractices.md`にチェック項目を追加・変更したら、`writing.md`（作成時の手順）と`evaluating.md`（評価時の観点）の両方が引き続き整合しているか確認する（特に評価用プロンプト例中の指示文言）
