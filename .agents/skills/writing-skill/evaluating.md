# 既存スキルの評価手順

既存の`SKILL.md`（および同梱ファイル）が[bestpractices.md](bestpractices.md)のベストプラクティスに沿っているかを評価する手順。新規作成・編集自体は対象外（→ [writing.md](writing.md)）。

## 手順

1. **対象スキルを特定する** — 評価対象の`SKILL.md`のパスと、同階層の同梱ファイル一覧をGlob/Readで確認する。対象が**3件以上**なら、下記「複数スキルを一括評価する場合」に従い必ずサブエージェントに委譲する（自分のコンテキストで直接読み込まない）。2件以下なら自分で評価してよい。
2. **[bestpractices.md](bestpractices.md)のチェックリストと1項目ずつ照合する** — 各項目を満たす/満たさないで判定し、満たさない場合は該当箇所（frontmatterの行、本文の節など）を具体的に記録する。
3. **見落としやすい観点を重点的に確認する**:
   - `description`: 三人称で書かれているか、「何をするか」+「いつ使うか（具体的なトリガー）」の両方があるか、ワークフローの要約になっていないか
   - 自由度: タスクの性質（決定論的で失敗が許されない／複数の正解がありうる）に対して、指示の具体度が適切か
   - 分割の妥当性: 条件分岐が「別スキルにすべきもの」を無理に1つの`SKILL.md`に詰め込んでいないか、逆に同一目的なのに不必要に分割していないか（判断基準は[writing.md](writing.md)の「条件分岐がある場合の設計判断」を参照）
   - 行数: `SKILL.md`本体が500行を超えていないか。参照ファイルが100行を超えるのに目次がないか
   - 参照の深さ: リンクが2階層以上ネストしていないか（`SKILL.md`→A→Bのような連鎖）
   - 動的コンテキスト注入すべき処理（環境情報の収集、事前チェックなど）が、エージェント任せの本文指示になっていないか
   - 同梱スクリプトがある場合、エラーハンドリング・マジックナンバーの説明があるか、決定論的ロジックが本文の疑似コードやBashワンライナーで済まされていないか
4. **問題点を「重大（修正必須）」「軽微（推奨）」に分けて報告する** — 各項目について、何がどう問題か、どう直せばよいかを具体的に示す。技術的な内容の正確性（ドメイン知識そのものの正しさ）は評価対象外。あくまで構造・書き方のベストプラクティス準拠を見る。
5. **修正が必要な場合はユーザーに確認のうえEditで直接修正する。** まとまった書き直しが必要なら[writing.md](writing.md)の手順に従う。

## 複数スキルを一括評価する場合

対象スキルが多いと、全`SKILL.md`と同梱ファイルを自分のコンテキストに読み込むだけで大量のトークンを消費し、以降のやり取りの質が落ちる。3件以上を評価する際は、Agentツールで並列サブエージェントに委譲し、自分は各サブエージェントへの指示出しと結果の統合に徹する。

1. **4件程度ずつバッチに分ける** — サブエージェント1体あたりの担当は**3〜4スキル**を目安にする。1体に詰め込みすぎる（5件以上）と評価の深さ・精度が目に見えて落ちるため避ける。役割が近い・重複しがちなスキル同士（例: 用途が似た複数スキル）は同じバッチに含め、使い分けの妥当性も併せて確認させる。
2. **各サブエージェントへの指示に必ず含めるもの**:
   - **[bestpractices.md](bestpractices.md)を最初にReadすること**という明示的な指示（評価基準そのものなので省略させない）
   - 参考として[writing.md](writing.md)（SKILL.mdの書き方の指針）も読ませる
   - 担当するSKILL.mdの絶対パス一覧（同梱ファイルも必要に応じて確認するよう指示）
   - bestpractices.md準拠に加えて、**それ以外の観点**も明示的に評価させる — 初見で読んですぐ用途が理解できるか、冗長でないか（逆に説明不足でないか）、記述と実装の乖離や古い情報がないか
   - 出力形式（スキルごとに: 総合評価の優先度／良い点／問題点／改善提案）と、バッチ内での優先順位ランキングを1行で添えること

   プロンプト例（`{{...}}`は動的に埋める箇所）:

   ```
   あなたはClaude Codeのスキル(SKILL.md)をレビューするタスクを行います。対象リポジトリは{{リポジトリルートの絶対パス}}です。

   ## 必須の準備作業
   まず必ず以下のファイルをReadツールで読み込んでください（これがベストプラクティスの基準です）:
   - {{bestpractices.mdの絶対パス}}
   - {{writing.mdの絶対パス}} （SKILL.mdの書き方自体の指針も参考にする）

   ## 評価対象（このバッチ担当分、以下{{N}}つのSKILL.mdとその同ディレクトリ内の付随ファイルを読むこと）
   1. {{対象1のSKILL.md絶対パス}}
   2. {{対象2のSKILL.md絶対パス}}
   {{...3〜4件まで}}

   各スキルについて、ディレクトリ内の同梱ファイル（reference/追加ドキュメント、スクリプトなど）があれば、必要に応じて中身も確認してください（全文精読は不要、参照されている構成や分量感を把握する程度でよい）。
   {{役割が近いスキル同士を担当させる場合のみ}}: {{対象X}}と{{対象Y}}は役割が近い/重複しがちなので、使い分けが明確か・説明に重複や矛盾がないかも確認してください。

   ## 評価観点
   1. **bestpractices.md に沿っているか** — description の書き方（トリガーになる語句が入っているか、曖昧すぎないか）、YAMLフロントマターの妥当性、ファイル構成（SKILL.md本体とreferenceの分離など）、記述スタイルなど、bestpractices.mdに書かれている基準に照らして評価。
   2. **読んですぐ意味が分かるか** — SKILL.mdを初見で読んだときに、いつ使うスキルなのか、何をしてくれるのか即座に理解できるか。曖昧な表現、専門用語の説明不足、構成のわかりにくさがないか。
   3. **冗長でないか** — 不要に長い、同じ内容の繰り返し、本来別ファイルに逃がすべき詳細がSKILL.md本体に埋め込まれすぎていないか、逆に説明不足すぎないかなど。
   4. その他、実用上の問題（説明と実装の乖離、リンク切れの可能性、古い情報など）があれば指摘。

   ## 出力形式
   各スキルごとに以下を簡潔にまとめてください（日本語で）:
   - スキル名
   - 総合評価（優先的に改善すべき度合い: 高/中/低）
   - 良い点（あれば簡潔に）
   - 問題点（具体的に、bestpractices.mdのどの基準に反しているか等を明記）
   - 改善提案（簡潔に）

   最後に、このバッチ{{N}}スキルの中で「優先的に改善すべき順」のランキングを1行でまとめてください。

   出力は日本語で、簡潔かつ具体的にお願いします。冗長な前置きは不要です。
   ```

   `writing-skill`自身を評価対象に含める場合は、bestpractices.mdの同梱元＝お手本という位置づけを踏まえ「それ自体がベストプラクティスに沿っているか、自己言及的に厳しくチェックしてください」の一文を追加すると精度が上がる。

3. **並列実行する** — 依存関係がないバッチ評価は、1回のメッセージで複数のAgent呼び出しをまとめて発行し並列化する。
4. **結果を統合する** — 各バッチの結果（と優先度ランキング）を集約し、全体を通じた優先度別（高/中/低）のサマリーにまとめてユーザーに報告する。個々のサブエージェントの生出力をそのまま貼らず、要点を絞る。共通して現れる問題パターン（例: 「参照ファイルに目次がない」が複数スキルで頻出）があれば、個別指摘とは別にまとめて言及すると気づきやすい。
