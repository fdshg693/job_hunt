# 引き渡しプロトコル（何を伝え、何を待ち、何を見ないか）

[SKILL.md](../SKILL.md) の Phase 2 の詳細。認証の主体はユーザーで、エージェントは**窓を用意して待つ係**。

## 渡すときに伝える 4 項目

これ以上は書かない。長い説明はユーザーが読まずに操作を始めるだけ。

1. **どの窓か** — 「いま開いた Chrome のウィンドウ」。他の窓では意味がないことを明示する
2. **何をしてほしいか** — 「`<site>` にログインしてほしい。MFA があればそこまで済ませて」
3. **こちらは見ていないこと** — 「ログインが終わるまでこちらは画面を読まない」
4. **終わったらどうするか** — 「ログイン後の画面まで来たら『終わった』と教えて。ウィンドウは閉じないで」

文例:

> Chrome を開きました（`<site>`）。この窓で直接ログインしてください。MFA があればそこまで済ませてください。
> ログインが終わるまで私は画面を読みませんし、パスワードや認証コードはこちらに貼らないでください。
> ログイン後の画面まで来たらそのまま**ウィンドウは閉じずに**「終わった」と教えてください。

## 待っている間にやってよいこと / いけないこと

| | コマンド |
|---|---|
| **やってよい** | `playwright-cli list`（セッションが生きているかの確認だけ）／`profiles.mjs list`・`show`・`path`（ブラウザに触れない） |
| **やってはいけない** | `snapshot` / `find` / `screenshot` / `pdf` / `state-save` / `cookie-*` / `localstorage-*` / `sessionstorage-*` / `run-code` / `eval` / `goto` / `reload` / `go-back` / クリック・入力系のすべて |

`goto` / `reload` / `go-back`（ナビゲーション系）も禁止に含める。認証フローの途中でページを動かすと
ユーザーの操作が壊れるうえ、この 3 つは `.playwright-cli/` にページ全体を書き出す（0.1.19 実測。
コマンド名は `navigate` ではなく `goto`）。`find` も禁止側にある点に注意 — ファイルは書かないが、
出力がそのままエージェントの会話に入るので、禁止の理由としては同じ。

**スクリプトが認証壁を検知して待つ場合は別の契約になる**（`run-code` を「返り値を URL / boolean に
限る」条件付きで使う）。[scripted-automation.md](scripted-automation.md) を参照。
ここで禁止しているのは**エージェントが手で撃つこと**で、そちらの緩和は適用されない。

**ポーリングしない。** 「もうログインできましたか？」と URL を覗く行為は、認証画面を読まないという
前提そのものを崩す。待つのは会話の側で、ブラウザの側ではない。

## 完了宣言を受けたあと

1. 最初の読み取りは、**認証ドメインではないページ**に対して行う。
   ログイン後の遷移先を `snapshot` して、想定の画面に来ているかを確認する
2. まだログイン画面なら、読み取りをそこでやめて「まだログイン画面のようです」とだけ伝え、再度待つ。
   何が足りないかを画面から読み取って助言しようとしない
3. 資格情報らしき文字列が `snapshot` に写り込んだ場合は、それを会話に出さない。
   「入力欄に値が入っています」程度に留める
4. ログイン成功を確認できたら、**プロファイルの説明を登録する**（次回この窓を使い回すため）:

   ```bash
   P=".claude/skills/sharing-browser-with-user/scripts/profiles.mjs"
   node $P register <site> --description "<何用か>" --url "<入口 URL>"
   node $P used <site>
   ```

   `--description` にメールアドレス・社員番号・テナント名など**アカウントを特定できる文字列を書かない**。
   ここは会話ではなくファイルに残る場所なので、snapshot と同じ基準で扱う

## 再ログインを頼むとき

2 回目以降の実行でログイン画面に当たったときは、原因をサイト側のセッション期限と切り分けて伝える:

> 前回のログイン状態が切れていました（プロファイルは残っています）。もう一度この窓でログインしてください。

プロファイルが壊れている／毎回ログインを求められる場合は
[troubleshooting.md](troubleshooting.md) の「毎回ログインを求められる」へ。

## ユーザーが資格情報を渡してきた場合

会話に ID / パスワード / MFA コードが貼られても**使わない**。

> 資格情報はこちらでは使いません。開いている窓で直接入力してください。

すでに貼られたものを消すことはできないので、そのままにする（削除を促すだけにする）。
その値を `fill` や `run-code` に渡す、ファイルに書く、環境変数に入れる、のいずれもしない。

## ユーザーが不在・応答がない場合

待ちが長引いたら、ブラウザを開いたままにして作業を中断し、状況を報告して終わる。
**勝手に閉じない**（ユーザーが認証途中かもしれない）。`close` はユーザーの指示か、
作業が完了したときだけ。
