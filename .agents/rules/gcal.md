# Google カレンダー連携ルール

Google カレンダーの空き時間・予定の参照と、予定の作成・更新・削除（`scripts/gcal/`）の運用ルール。仕様・手順の正本は [`docs/gcal/README.md`](../../docs/gcal/README.md)、共通認証・スコープは [google-api.md](google-api.md)。

## 書き込み（`manage_events.py`）

- 予定の作成・変更・削除の前に、内容（日時・タイトル・場所）をユーザーに提示して確認を取る。作成は面談確定などユーザーの意思が明確なときに限る。迷ったら先に `--dry-run` で見せる。
- 更新・削除は既定でこのツールが作った予定（`extendedProperties.private.job_hunt_managed=1`）だけ。それ以外を変えるときはユーザーの明示確認を取ってから `--force` を付ける。
- 自分が主催者でない予定（企業からの招待）・ゲストのいる予定は変更・削除しない。このガードを外すオプション・コードを追加しない。リスケ・辞退は相手への連絡（ユーザーが行う）で扱う。
- 招待メールを送らない（`sendUpdates=none` 固定、attendees を扱わない）。相手への連絡はユーザーがメール等で行う。Meet 等の会議を自動生成しない。
- 確定日時の正は vault の企業ログ（`next_due`）。カレンダーを変えたら vault も合わせる。予定 ID は vault のフロントマターに持たせず、`job_hunt_company_key` で逆引きする。

## 候補枠算出・提示の基本原則（目いっぱい提示・順序の絶対遵守）

- **面談最優先・バッファなし（`--buffer 0`）**:
  - 空き枠算出（`find_slots.py`）時は面談を最優先とする。前後に安全マージン（バッファ）を取ってはならない（必ず `--buffer 0` を指定する）。
  - 既存予定の間（例: 12:00まで予定、次が14:00〜なら `12:00〜14:00`、14:00〜15:00の予定と17:00〜17:30の予定の間なら `15:00〜17:00`）を目いっぱいに使う。
- **目いっぱい提示・ユーザー側での間引き（順序の絶対遵守）**:
  - 候補枠は**基本的に目いっぱい（全枠・各日の目いっぱいの時間帯レンジ）提示**する。
  - AIが勝手に「3〜5枠に絞る」「日中と夜を分散して一部を削る」などと候補日時を間引いたり省略したりしてはならない。
  - 不都合・不要な枠があれば**ユーザーが自分で間引く**。
  - **絶対にこの順序を逆にしない**（AIが事前間引きした結果、ユーザーが本来選べたはずの候補枠が存在しないものと誤認される重大な事故を防ぐ）。

## 情報の扱い

- 予定タイトル・説明に `visibility: internal` の情報（fit_score・本音メモ・足切り判断）を書かない。タイトルは `【面談】{会社名} {ステージ}` 程度にとどめる。
- 私用予定の中身（タイトル等）を vault・公開同期対象に書かない。生データは `data/gcal/`（gitignore 済）にだけ置く。
- カレンダー ID・予定 ID を docs・tests・scripts に書かない。
- 面談可能な時間帯・曜日などユーザー固有の希望は vault（track の `strategy.md` 等）を正とし、コードの既定値に書かない。
